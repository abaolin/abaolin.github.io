## 核心内容提炼

`scipilot-figure-skill` 是 Haojae 发布的 SciPilot Skills 家族成员，定位不是“帮你把 matplotlib 代码写出来”，而是一个面向科研论文的图表顾问：先理解数据与论证目标，再选择图型，最后按期刊规范完成绘制、检查和导出。

它最有价值的地方在于把科研制图拆成一条可审计的工作流：数据剖析、图型选择、错误拦截、期刊规格、CJK 字体、出图自检和多格式导出。对经常写论文、做实验图、准备 Nature / Science / IEEE / Elsevier / PNAS 或中文期刊图件的人来说，这类 Skill 的意义不只是省时间，而是把“图是否能支撑结论”这件事前置。

> 由 claude-opus-4-8 模型总结提炼，观点仅供参考。

## 它解决的不是画图，而是选图

很多科研图的问题并不来自代码能力，而来自一开始就选错了表达方式。仓库 README 里的对比很直接：普通画图工具往往按用户指令执行，比如“画柱状图”；而 `scipilot-figure-skill` 会先做 EDA，检查列类型、样本量、分布、异常值和相关性，再追问这张图到底要证明什么。

这个差异很关键。科研图不是装饰，也不是数据截图，而是论文论证链条的一部分。图型选择如果和论点不匹配，后面把配色、字号、DPI 做得再漂亮，也只是把错误包装得更精致。

## 8 步工作流

这个 Skill 把论文制图拆成 8 个步骤：

1. 理解任务：确认这张图要论证什么、数据在哪里。
2. 剖析数据：用 `profile_data.py` 分析列类型、样本量、分布、异常值和相关性。
3. 选择图型：参考 `chart_selection.md`，根据数据形态和论证目标做决策。
4. 主动拦截：遇到典型误用时参考 `viz_pitfalls.md`，例如小样本均值柱状图。
5. 查期刊规范：根据 `journal_specs.md` 确认栏宽、字号、DPI 和字体。
6. 配置绘图环境：用 `setup_style.py` 应用期刊预设和 CJK 字体。
7. 绘制图件：通过 `plot_recipes.md` 覆盖常见图型配方。
8. 自检与导出：执行程序自检、AI 读图检查，并用 `export_figure.py` 导出多格式结果。

这套流程的好处是把“凭经验画图”变成了“按约束做决策”。它不是替代研究者判断，而是把研究者容易忽略的检查项系统化。

## v2.1 的关键增强：出图后的自检闭环

v2.1 里最值得看的能力是视觉自检闭环。普通绘图脚本经常在 `savefig()` 后就结束，问题要到投稿、排版或审稿阶段才暴露：中文变方框、负号显示异常、图例压住数据、刻度标签重叠、子图 a/b/c 没对齐。

`scipilot-figure-skill` 把这件事拆成两层：

- 程序自检：`visual_qa.audit_layout()` 捕获缺字、乱码、文字裁切、刻度标签重叠等确定性问题。
- AI 读图：渲染 PNG 后，让多模态模型检查图例遮挡、子图编号对齐、灰度可分辨性等更偏感知的问题。

这个设计很实际。程序适合抓硬规则，AI 适合抓“看起来不对劲”的问题，两者组合比单纯 lint 或单纯人工检查都更贴近投稿前的真实质量控制。

## 它会主动拒绝哪些坏图

README 中列出的几个拦截点很有代表性：

- `n < 10` 的组间比较，不建议只画均值柱状图，因为它会掩盖分布，优先改成箱线图叠加 stripplot。
- 双 Y 轴容易制造并不存在的相关性，建议拆成子图或先标准化。
- 饼图和 3D 柱状图通常信息效率低，建议改成横向柱状图。
- Y 轴截断如果没有明示，会误导读者。
- 分类变量不应随手用折线连接均值。
- rainbow / jet 色图容易造成视觉误判，应改用 viridis、RdBu_r 或色盲友好方案。
- 一张图塞太多论点时，应拆图，让每张图服务一个结论。
- 中文和负号乱码要在导出前被拦截，而不是等到投稿 PDF 里才发现。

这些规则看似琐碎，其实正是论文图最常见的翻车点。好图不是“更炫”，而是更难误读。

## 五条硬性原则

这个项目把论文图规范压缩成五条硬规则：

1. 按最终尺寸出图，不二次缩放，例如 Nature 单栏直接设定 `figsize=(3.5, 2.625)`。
2. 数据图优先导出 PDF / SVG / EPS，照片类素材才用 TIFF / PNG，避免用 JPEG 承载数据图。
3. 默认使用色盲友好配色，例如 Okabe-Ito，并通过冗余编码增强可读性。
4. 字号必须在最终尺寸下可读，正文 7-9 pt，最小不低于 6 pt。
5. 误差表达必须说清楚，图注应标明 SD / SEM / 95% CI、样本量 n 和检验方法。

这几条很“审稿人视角”：它们不是美学建议，而是减少误读、减少返工、减少投稿阶段格式事故的工程约束。

## 对中文科研写作特别友好

中文图件常见两个坑：中文字体缺失和负号显示为方框。这个 Skill 的 `setup_style(lang='zh')` 会按优先级查找 `Noto Sans CJK SC`、`Source Han Sans SC`、`SimHei`、`Microsoft YaHei` 等字体；找不到时给出清晰提示。它还支持中文期刊里常见的“宋体 + Times New Roman 数字”混排。

这类细节对英文工具链很容易被忽略，但对中文论文和中文演示稿非常现实。图表一旦进入论文版式，字体问题往往比代码问题更讨厌。

## 适合什么场景

我会把它放在三类场景里使用：

- 论文投稿前：把实验图按目标期刊规格重做，并跑一轮视觉自检。
- 研究早期探索：面对一份 CSV，不急着画图，先剖析数据并讨论图要支撑什么论点。
- 多面板 Figure 组装：例如 PCA、loss 曲线、混淆矩阵、生存曲线组合成 Figure 1，需要统一字号、配色、子图标签和导出格式。

不太适合的场景是一次性随手画个运营图、营销图，或者只追求视觉冲击的展示图。它的设计重心明显在“科研论证”和“出版规范”，不是通用可视化模板库。

## 我的判断

`scipilot-figure-skill` 的真正亮点不是封装了多少 matplotlib recipe，而是把科研制图中的隐性判断显性化：先问论点，再看数据，再选图型，最后用规范和自检兜底。

这也是 Agent Skill 这类工具值得期待的方向。它不只是把一段命令自动化，而是把一个领域里的判断框架、反模式和质量门槛装进工作流里。科研制图尤其适合这种形态，因为它既有明确规范，又有大量“看起来能画，其实不该这么画”的经验坑。
