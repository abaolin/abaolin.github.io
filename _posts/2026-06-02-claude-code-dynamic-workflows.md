## 核心内容提炼

Claude Code 推出动态工作流功能，让 Claude 能够动态编排并行运行的数十到数百个子代理，自动拆解任务、交叉验证结果，端到端完成原本需要数周乃至数季度的复杂工程任务，如全库 Bug 排查、大规模迁移和高风险方案验证。

> 由 claude-opus-4-8 模型总结提炼，观点仅供参考。

## 什么是动态工作流

动态工作流（Dynamic Workflows）让 Claude 能够独立编写编排脚本，在单次会话中调度数十到数百个并行子代理，并在结果交付给你之前先行自检。

传统模式下，单个代理一次处理的任务规模有限，尤其面对复杂、老旧的代码库时更显吃力。而动态工作流擅长应对这类大型挑战：

- 跨整个服务的 Bug 排查
- 涉及数百个文件的大规模迁移
- 在落地前需要从各个角度反复压力测试的方案

这些任务都能被端到端地完成。原本需要按季度规划的工作，现在可能几天就能收尾。

目前该功能以研究预览（research preview）形式开放，覆盖 Claude Code CLI、桌面端与 VS Code 插件，适用于 Max、Team 及 Enterprise（需管理员启用）方案，同时支持 Claude API、Amazon Bedrock、Vertex AI 和 Microsoft Foundry。

> 注意：动态工作流的 token 消耗远高于普通 Claude Code 会话，建议先从一个范围明确的小任务入手，感受实际用量。

## 如何启动工作流

为获得最佳体验，使用动态工作流时建议开启 auto 模式。之后有两种启动方式：

1. **直接让 Claude 创建工作流**，例如输入「Create a workflow」。
2. **开启 `ultracode` 设置**：这是 Claude Code 专属选项，可在 effort 菜单中找到。它会将努力级别设为 `xhigh`，并让 Claude 自行判断何时启用工作流来处理你的任务。

## 动态工作流的实战场景

内部团队和早期试用者已经将动态工作流应用于多种场景：

- **全库级别的审计任务**：包括 Bug 排查、基于性能分析器的优化审计、安全审计。Claude 并行搜索整个服务或仓库，再对每一项发现进行独立验证，从而让报告只呈现真实问题。同样的模式也适用于安全加固，比如批量检查鉴权逻辑、输入校验和不安全写法。

- **大规模迁移与现代化改造**：框架替换、API 弃用处理、跨越数千文件的语言移植，都能端到端完成。

- **需要双重把关的关键工作**：当答案出错代价高昂时，工作流会让 Claude 对同一问题做出多次独立尝试，并安排对抗性代理在结果交付前主动尝试推翻它。

> 「动态工作流在大型代码库的探查与评审任务上尤为有价值。我们用它识别死代码、发现传统静态分析遗漏的清理机会，效果显著，让工程师在维护和重构上推进得更快。」

> 「动态工作流填补了『触发单个子代理』和『搭建完整代理团队』之间的空白。从规划到实现一气呵成，让我们能放心地运行更长的任务而不失去可见性。」

## 案例：用动态工作流重写 Bun

展现动态工作流规模化能力的一个典型案例，是近期对 Bun 的重写。Jarred Sumner 借助动态工作流，把 Bun 从 Zig 移植到 Rust：

- 现有测试套件的 **99.8%** 通过
- 生成约 **75 万行** Rust 代码
- 从首次提交到合并仅用了 **11 天**

整个过程被拆分为多个阶段：

1. 第一个工作流为 Zig 代码库中每个结构体字段映射正确的 Rust 生命周期。
2. 下一个工作流将每个 `.zig` 文件改写为行为完全一致的 `.rs` 移植版本——数百个代理并行工作，每个文件配两名审阅代理。
3. 一个修复循环持续驱动构建和测试，直到两者都干净通过。
4. 移植完成后，一个通宵运行的工作流处理了不必要的数据拷贝，并为每处改动单独开 PR 供最终评审。

虽然尚未投入生产，但以上全部由动态工作流自动完成。

## 工作原理

工作流启动后，Claude 会根据你的提示动态规划，将任务拆解为子任务，并把工作分散到并行运行的子代理上。

- 结果在合并前会先经过检查；你最终拿到的是一个统一、协调的答案。
- 多个代理从不同角度切入问题，另一些代理则尝试反驳已有发现，整个运行持续迭代直到答案收敛——这正是工作流能达到单次处理无法企及的效果的原因。

动态工作流为并行和长时间运行的工作而生，运行时间可延伸至数小时乃至数天，用以完成此前需要数周的最复杂工程任务。

关键设计点：

- **进度自动保存**：任务中断后可从断点续跑，而非从头开始。
- **编排在对话之外进行**：无论任务规模多大，计划都能保持在轨。
- **用量更高**：首次触发工作流时，Claude Code 会展示即将运行的内容并请求确认。组织管理员也可通过托管设置选择禁用工作流。

## 如何开始使用

- **Max 或 Team 方案**，以及通过 API 使用 Claude Code 的用户：动态工作流默认开启。直接让 Claude 创建工作流，或开启 `ultracode` 设置即可上手。
- **Enterprise 方案**：发布时默认关闭，管理员可在 Claude Code 设置中轻松启用。

更多细节可查阅官方文档。
