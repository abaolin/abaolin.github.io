## 核心内容提炼

随着前沿 AI 模型把"漏洞发现到被利用"的时间从数月压缩到数小时，传统以边界为核心的安全防御已无法应对自治 AI Agent 带来的全新攻击面。Agent 不再执行预定义逻辑，而是自主解读目标、选择工具、执行多步操作，这使得它们既会被 AI 加速的攻击波及，又会因自身的自治性被操纵在"合法权限"内造成机器速度的破坏。

本文的核心主张是：**用零信任（Zero Trust）原则为 Agent 部署奠定基础**——永不信任、始终验证、假设已被攻破。围绕这一前提，企业需要构建可验证的 Agent 身份、短时令牌与硬件绑定凭证、最小代理能力（Least Agency）、运行时供应链审查、记忆与 RAG 防污染机制，并以分层（Foundation / Enterprise / Advanced）的方式逐步推进，最终把"为攻破而设计"落实到每一个 Agent 的爆炸半径上。

> 由 Claude 模型总结提炼，观点仅供参考。

## 面向下一代威胁的安全建设

边界安全的失效在 AI 时代被双重放大。第一，承载 Agent 的基础设施和企业其余资产一样，暴露在 AI 加速的攻击之下；第二，Agent 本身引入了"自治"——它能解读模糊指令、自行编排工具链。传统访问控制无法阻止 Agent 滥用合法权限，而监控也必须考虑那些"靠持久性而非单次漏洞利用取胜"的攻击。

值得注意的是，最具优势的组织不一定拥有最先进的 AI，而是那些**基本功足够扎实**、自身代码被 AI 扫描时漏洞更少、并且从第一天就按"会被攻破"来架构 Agent 部署的组织。对于医疗、金融、政府等受监管行业，这套框架的价值在于：验证 Agent 行为、授予最小必要权限、在被攻破时收敛损害。

## 零信任的核心原则

零信任的概念可追溯至 1994 年 Stephen Paul Marsh 的博士论文，并在多起边界防御失效的重大泄露事件后获得动力。NIST SP 800-207、NSA 的零信任实施指南（ZIGs）等共同将其编纂为可落地的原则。零信任用一句话替代了边界安全：**信任为零，验证一切，假设已被攻破。**

三条核心原则：

- **永不信任，始终验证**：每个访问请求无论来源都要经过认证与授权，来自企业内网的请求和来自外部 IP 的请求受到同等审查。
- **最小权限**：只授予完成特定任务所需的最小访问权，借此收敛任何单点被攻破的爆炸半径。
- **假设已被攻破**：在设计时就假定攻破终将发生，目标不是"防止入侵"而是"限制损害"，通过按身份隔离、细粒度访问控制确保攻破一个系统不会波及其他。

**一个设计性的检验标准——"不可能"，而非"麻烦"。** 评估任何控制项时只问一个问题：它让攻击变得不可能，还是只是变麻烦？靠摩擦取胜的缓解措施（额外跳板、限速、非标准端口、基于短信的 MFA）在面对"有无限耐心、单次成本近乎为零"的 Agentic 攻击者时会显著退化。能通过这一检验的控制项有共同特征：**硬件绑定凭证、过期令牌、加密身份、以及根本不存在的网络路径（而非仅仅不便的路径）。** 当犹豫不决时，优先选择"移除某项能力"的控制，而非"限速某项能力"的控制。

## 一、自治系统的安全考量

Agentic AI 引入了既有安全模型未曾设计应对的能力：

- **无需人工逐步发起或批准**：Agent 可自主搜索、综合、产出报告，效率背后意味着被操纵的 Agent 能以机器速度造成伤害。
- **工具访问**：Agent 通过 API、数据库、文件系统、外部服务及 MCP（Model Context Protocol）交互，一个被攻破的 MCP 栈可导致数据窃取、恶意代码执行与破坏。
- **决策的模糊性**：Agent 需解读指令并自行选择实现方式，对人类无害的指令可能被解读出截然不同的结果。
- **上下文持久化**：跨会话记忆提升能力，也带来新的数据保护需求。
- **多 Agent 协同**：Agent 间的信任关系让攻击者得以攻破一个 Agent 后横向跳转，触及初始目标无法直接到达的系统。

几个关键概念：

- **爆炸半径（Blast radius）**：衡量出错时的潜在损害。只读单库的 Agent 半径很小，拥有云基础设施管理权限的 Agent 半径巨大；安全投入应与暴露面匹配，并假定每个 Agent 的爆炸半径终将被测试。
- **最小代理能力（Least Agency）**：OWASP 提出，将最小权限扩展到 Agent。它进一步约束**每个 Agent 工具能做什么、做多频繁、在哪里做**——数据库工具只读、邮件摘要器无发送/删除权、API 仅最小 CRUD。

在合规层面，零信任与现有监管要求相互增强。美国、英国、澳大利亚政府均已发布零信任指南，美国更要求所有联邦机构在 2027 年前采用零信任。

## 二、Agentic 系统当前面临的威胁

OWASP 识别出的主要威胁包括提示注入、工具与资源劫持、身份与权限滥用、记忆与上下文污染、供应链风险。

**提示注入与指令操纵**

- **直接注入**：攻击者构造输入覆盖系统指令，技术手段包括显式指令覆盖、Base64/十六进制等编码绕过、以及对人类无意义但能影响模型输出的对抗性后缀。研究显示算法化方法可实现 100% 攻击成功率，且提示能跨多个模型家族迁移。
- **间接注入**：更阴险——攻击者把恶意指令嵌入 Agent 会处理的外部数据（网页、邮件）中。Microsoft Research 证实 LLM 无法可靠区分"信息性上下文"与"可执行指令"，用户看不到载荷，Agent 却把它当作合法请求执行。

**工具与资源滥用**

- **工具投毒**：攻击者篡改 MCP 工具描述符、Schema 或元数据，使 Agent 基于伪造能力调用工具。首个在野恶意 MCP 服务器伪装成合法邮件服务，秘密复制所有发出的邮件。
- **拉地毯（Rug pull）**：合法工具被悄然替换为恶意版本。
- **工具链攻击**：诱使 Agent 把多个合法工具组合成有害序列（如串联内部 CRM 与外部邮件工具外泄客户数据）。由于命令都通过受信任二进制、以有效凭证执行，以主机为中心的监控看不到恶意软件，滥用难以察觉。
- **资源耗尽**：循环放大让 Agent 反复调用昂贵 API，造成拒绝服务或账单暴涨。

**身份与权限滥用**

- **无约束权限继承**：高权限管理 Agent 不做最小权限收敛就委派任务，把完整权限上下文传给本应受限的工作 Agent。
- **混淆代理（Confused deputy）**：被攻破的低权限 Agent 把"看似合法"的指令转发给高权限 Agent，后者在未核实原始用户意图的情况下执行。
- **基于记忆的权限保留**：Agent 缓存凭证或密钥而未做记忆隔离，攻击者可诱导其取出此前安全会话缓存的密钥，跨会话边界提权。

**供应链与依赖风险**

Agentic 生态常在运行时动态组合能力、加载外部工具与人格，攻击面超出传统软件成分分析（SCA）所能覆盖，而前沿模型擅长识别"已修补但上游未修补"漏洞的特征。

- **工具与框架供应链**：PyTorch 依赖混淆攻击在安装时外泄 SSH 密钥；研究者在主流平台发现约 100 个恶意 AI 模型，部分在加载时反向连回攻击者。
- **模型供应链**：投毒权重与被污染的微调数据可植入后门。Anthropic 研究表明，注入仅 250 份恶意文档即可为 6 亿到 130 亿参数的 LLM 植入后门，且后门能在监督微调与 RLHF 等安全训练中存活。
- **开源健康度**：多数供应链以开源为主且无 SLA。可用 OpenSSF Scorecard 对每个依赖按分支保护、模糊测试覆盖、签名发布、维护者活跃度评分；同时把"是否在为加速的漏洞利用周期做准备、是否扫描自身代码"纳入对第三方供应商的尽调。把前沿模型指向你的 lockfile 做一小时依赖树审计，往往能发现值得做的依赖收敛。

**记忆与上下文污染**

- **RAG 投毒**：通过被污染的来源、直接上传或过度信任的管道，把恶意数据注入向量库，Agent 检索到被污染上下文后产出错误答案或执行定向载荷。
- **共享上下文污染**：多租户环境中，攻击者经正常交互注入数据影响后续会话，新会话可能继承被污染的上下文。更隐蔽的是**长期记忆漂移**——摘要或同伴 Agent 反馈逐渐改变存储知识或目标权重，因没有单次明显恶意而难以检测。

逐个追逐威胁只会让你陷入被动，零信任原则才提供更持久的基础。

## 三、将零信任应用于 Agentic AI 服务

本框架以三个能力层级递进，每一层都在前一层基础上加固而非替换：

- **Foundation（基础）**：适合小型部署或初始实施的最小可行安全。由于 AI 加速攻击压缩了利用周期，基础层的"地板"已被抬高——**仅靠摩擦的控制不再合格**。
- **Enterprise（企业）**：多数有显著部署规模的组织应瞄准的标准实践。
- **Advanced（进阶）**：对多数组织是愿景级，对高风险/严苛监管部署则是基线。

需要预期：随着空间演进，Advanced 会成为 Enterprise 标准，Enterprise 会下沉为 Foundation。

**Agent 身份与认证**

身份是其他一切安全能力的地基——没有可验证身份，就无法强制访问控制、维护审计追踪、归因行为。

- **身份验证**：Foundation 要求为每个 Agent 实例分配**加密支撑的持久 ID**（不只是标签），覆盖从创建到退役的全生命周期，并出现在所有日志与访问请求中。仅有唯一标识只是"贴标签"，必须加密生根，让身份伪造真正变难。
- Enterprise 引入基于 X.509 证书的认证与生命周期管理（含轮换与吊销），并要求**双向 TLS + 证书钉扎**以防中间人。
- Advanced 走向**硬件绑定凭证与认证签发**，把凭证绑定到硬件身份，使其无法从被攻破主机外泄，并将每一次服务间调用根植于经证明的硬件。

**服务认证**

建立 Agent 身份只解决一半问题，Agent 访问数据库、API 时还须证明身份。**静态 API Key 与共享服务账户密码**是模型辅助代码分析最先找到的目标，已不再是合法入口——即便在 Foundation。新的基线是由身份提供方签发的**短时、窄作用域令牌**：

- Foundation：以 OAuth 2.0 等令牌认证，过期时间以分钟计、自动刷新、绝不把凭证写入代码或配置。
- 若你今天仍在用"API Key + 轮换策略"，应把它视为已知缺口而非合规姿态——能从 lockfile 里 grep 出来的凭证，轮换并不会显著提高 AI 辅助攻击者的成本。优先转向短时令牌，并尽可能把凭证绑定到硬件。

**访问控制与权限管理**

即便认证完美，过度授权的 Agent 依然会造成损害。授权层负责强制最小代理能力：

- Foundation：**默认拒绝 + RBAC**，按 Agent 功能定义角色、分配每个角色所需的最小权限、阻断一切未显式授予的访问。把它当作起点而非终点。
- Enterprise：引入 **ABAC**，把时间、位置、数据敏感度、风险评分等请求属性纳入授权决策，并按上下文动态调整策略。

权限作用域（Privilege scoping）是最小代理能力的实际落地：在 Foundation，Agent 只获得任务所需的静态权限。

## 四、Agent 实施工作流

将原则转化为部署，应遵循一条贯穿身份、权限与运行时的工作流：先以加密身份与短时令牌建立可验证基线，再以"默认拒绝 + 最小作用域"约束 Agent 能力，对每一个工具实施最小代理能力（限定动作、频率、范围），并对运行时动态加载的工具、模型与依赖进行供应链审查。对持久记忆与 RAG 管道做分段与来源校验，阻断跨会话提权与上下文污染。整个流程的设计前提始终是"为攻破而设计"——让每个 Agent 的爆炸半径在被测试时损害可控。

## 五、以自治威胁的速度运营防御

当攻击者具备无限耐心与近零成本时，防御也必须自动化、可观测、可快速收敛。监控需要面向"靠持久性取胜"的攻击：以加密身份做非否认归因，在所有日志中追踪 Agent ID，关注跨会话、跨工具链的异常组合，而非仅依赖以主机为中心、看不到"合法凭证滥用"的检测。运营层应把可吊销的短时令牌、动态调整的策略与硬件绑定身份结合起来，在攻破发生时迅速隔离并收敛损害。

## 从原则到实践

本文呈现的是一套面向 Agent 安全架构的当前思考与最佳实践框架：以零信任为根基，用分层方式从 Foundation 走向 Enterprise，再向 Advanced 演进。它不替代针对具体环境的法律、合规或安全保证，而是为你自己的评估提供框架。在 AI 加速攻防的时代，**能否从第一天就为攻破而架构**，往往比拥有最先进的模型更能决定组织的安全韧性。
